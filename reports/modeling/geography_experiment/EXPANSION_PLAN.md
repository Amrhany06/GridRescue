# Proposed 20-county geography follow-up

The next experiment should use **20 counties in five states, four counties per state**. Multiple counties in each state let the state indicator represent a shared category. A full state holdout then tests what happens when both models encounter a previously unseen state. Start the extraction only after separate authorization.

## 1. Select counties before building labels

1. Use the exact four verified development files for 2018–2021. Scan each file separately with PySpark and save a compact county/state/year coverage table with usable quarter-hour counts per month, presence across all twelve months, and invalid and conflicting-key counts. Count distinct valid grid-aligned timestamps. A timestamp with conflicting reported values must be excluded when qualifying the final candidate counties. Exact duplicate rows count once. Compute coverage against 96 nominal slots per calendar day, including leap day in 2020. The source's year-end truncation is part of the measured coverage.
2. Start with California, Florida, Texas, Illinois and New York. Require at least 90% observed coverage in **each** development year, records in every calendar month, a stable five-character FIPS, and consistent state mapping. The existing Los Angeles, Miami-Dade and Harris counties qualify under these rules and can anchor the first three state groups. The other states and counties are candidates pending the coverage audit. If Illinois or New York cannot supply four qualified counties, use Pennsylvania, Ohio, North Carolina, then Washington as a predeclared reserve order.
3. In each state, rank qualified counties by their lowest annual coverage, then use ascending FIPS to break ties. Select four and keep the existing exemplar in California, Florida and Texas. Assign county roles before computing any labels. Within each of the four seen states, hold out one of the non-exemplar counties by a fixed seed-17 hash of the FIPS. Hold out New York in full, or its first qualifying replacement. Record the selection rules, qualified and rejected counts, exact county IDs, split roles, year files and hashes in a new manifest. No escalation prevalence, ML scores, or 2022 outcomes enter selection.
4. Retain all four years for each selected county. A 15-county resource fallback uses five states with three counties each, moving one of each seen state's three counties to its unseen-county group. Thirty counties should wait until a 20-county pilot measures the cost and coverage of scaling beyond the first run.

## 3. Run on Windows with measured resource gates

- First run the existing `scripts/preflight.py --development-fixtures` from the native Windows `.venv`. Use the verified Hadoop 3.3.4 native Parquet writer. The bounded Arrow-local wrapper caps outputs at 500,000 rows, so it does not cover the projected expanded scope. [Windows native storage verification](../../WINDOWS_NATIVE_SPARK_FIX.md).
- Use one development-only coverage pass and one extraction pass. Ingest one year at a time. Persist only compact coverage aggregates and selected records. Filter county IDs at ingestion before cleaning and Spark joins or windows. Write isolated native Parquet by year after each validated stage. Run temporal feature and label windows across all available adjacent-year records for each county, keeping exact-time lag semantics and three-hour purges. Year partitioning is a storage layout. It cannot split the data used for a single county's time window.
- Reuse the working Spark settings as a starting point (`local[2]`, 2 GiB JVM driver) and start the enlarged shuffles with about 16 partitions. Set a dedicated local scratch directory and collect telemetry for JVM and Python memory, shuffle spill and free disk by year. About 24 GiB system RAM, 5.5 GiB available RAM, and 10.2 GiB free disk were observed at planning time. Keep the Spark materialization and Python fits sequential and recheck free resources before the authorized run.
- The prior four-year Spark integrity scan took about 210 seconds and the three-county extraction took about 109 seconds. Coverage aggregation, deduplication and temporal windows require additional shuffle and disk work, so those timings establish only a reference for scans. Pilot one year of extraction and the first chronological fit for each variant, record wall time, peak working set and spill, then set the remaining run budget from those measurements. Reserve a separate output directory and preserve completed per-stage and per-fold reports for restarts.
- Keep the 100-tree configuration, fixed threshold and two fit workers. Fit one variant at a time and retain only required columns in Python. With 1.22 M training rows, a dense 13-column float64 input matrix alone is roughly 121 MiB, and an augmented matrix with 12 county indicators roughly 233 MiB. DataFrame overhead, preprocessing copies and forest storage add to these figures. Check measured peak memory before launching all 12 fits. The 15-county fallback or lower concurrency can reduce resource requirements with the same study design.

## 4. Test time and geographic transfer separately

| 2021 evaluation group | Fit history | What it measures |
|---|---|---|
| **Seen counties** (12) | All selected training counties through 2020 | Time transfer and whether identity helps for locations the model already knows. |
| **Unseen counties in seen states** (4) | Exclude all years of those county IDs from fitting and preprocessing | Whether a learned state category transfers within a state. FIPS encodes as an all-zero block. |
| **Unseen state** (4) | Exclude all records from that entire state from fitting and preprocessing | Performance when both location encoders yield all-zero blocks. |

On training counties, run the same three purged chronological folds and fit imputation, scaling and encoding independently in each fold. Before looking at the held-out geographic groups, use only 2018–2020 for any internal checks. For a spatial validation rehearsal, leave one county out per seen state in the earlier training block and score it in a later block. Keep the twelve-slot target contract and use class threshold 0.5 throughout. Valid past features from the held-out county may be calculated using its own observations available at the scoring time. Those rows must never fit the preprocessing or classifier.

Report pooled AP, all fixed-threshold metrics, and per-county AP, prevalence and confusion matrices for each evaluation group. Compare county-macro and pooled results with paired fold/county deltas and a grouped uncertainty analysis that respects county clustering and time dependence. Track the count of unknown-category predictions and compare them against the numeric baseline on identical anchors. A useful geographic signal should improve more than the observed variation and should help several unseen counties. The primary comparison keeps `max_features='sqrt'`. If the pilot leaves time in the approved budget, predeclare a separate one-fold sensitivity run using `max_features=3` for all three variants to hold the nominal number of candidate split features constant. Reserve the 2022 holdout and any decision to change the frozen pipeline for separate approval.
