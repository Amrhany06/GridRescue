# Leakage and validation audit

**VERIFIED for the observed development cohorts.** Spark windows, the fitted feature list and the keyed data agree on the prediction time. The original Spark preparation path and official Task 3 model are distinct from the local experimental XGBoost path. The Task 1–3 notebooks describe the earlier workflow. The experimental champion is built by `reports/modeling/local_improvement/train_local.py`, through `county_expansion/train_cohort.py::make_variant` and `src/gridrescue/experiment.py::fit`. The project's original 0.5 decision rule applies to the earlier protocol. The experimental cutoff has its own chronological selection record.

**P1 comparison protocol.** Before further tuning, version `reports/modeling/cloud_expansion/experiment_manifest.json` or a sibling development protocol. Declare eligibility, grouping unit, allowed years, county roles, primary metric, policy and stopping rule. Use inner chronological folds within outer time/state splits for settings and thresholds. Freeze outer states before computing labels using only coverage from data available at selection time. Preserve the historical 20-county benchmark as a named secondary comparison. Tests in `tests/test_modeling.py` and `reports/modeling/cloud_expansion/test_cloud.py` should inject held-out FIPS, a label ending exactly at a boundary, duplicate keys and unknown categories. Accept zero fit/outer-state intersections and zero crossing horizons, complete key/label identity within comparisons, explicit eligibility denominators, and an untouched outer fold for every reported tuning choice. Existing scores need relabeling as development evidence only. A new generalization estimate requires new outer fits.

**P1 reproducibility defect, verified by inspection.** `local_improvement/train_local.py::tune_one` resumes a candidate when score and detail files exist. File presence does not bind them to the active code, predictor values, estimator settings or environment. Later key alignment would catch changed keys, but could accept new values on identical keys. No evidence of stale scores in the champion. Before reusing this local runner, include a digest of ordered feature content, split identities, settings, code and pinned environment in each checkpoint manifest. Reject mismatches before reuse. Test an identical-key change in one predictor and a changed depth/seed; each must force a fresh run directory or fail closed. No retrospective refit required unless provenance disagrees. The cloud runner already includes code and environment in its run identity.

Independent tests executed here: seven `precision_diagnostic/test_diagnostic.py` cases passed, covering score ties, rate denominators, key/label alignment, purge boundary, hour-only ablation contract, hourly aggregation and model-reload precision. Existing Spark tests in `tests/test_pipeline.py` and `local_improvement/test_history.py` cover conflicts, missing exact slots, future perturbations and county isolation. The full Spark suite was not rerun in this audit.
